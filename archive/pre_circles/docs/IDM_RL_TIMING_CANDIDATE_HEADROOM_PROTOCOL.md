# RL Timing-and-Candidate-Headroom Protocol (Overnight Goal, Phase A)

**Status:** frozen before any new action-sweep outcome is examined. No RL
training is authorized by this document.
**Date:** 2026-08-30
**Goal:** determine whether P30 *timing* (recurrence 1/2/3) and *candidate
selection* (rank 1 vs rank 2) give learnable paired-value headroom over the
fixed rule, then (only through the staged gates) development-evaluate a
paired option-level policy. Work is development-only; no prospective seed is
used.

## 1. Eligible cells, cohort and grouping

- CAV penetration: **0.05 and 0.10** only (the supported operating domain;
  outside it the controller abstains).
- Demands: **1900, 2000, 2100 veh/h** (no critical density assumed; demand is
  a deployment-known cell variable and is reported per cell but is not a
  learned per-decision feature unless a future versioned protocol declares
  it).
- Landmark: frozen `risk_onset`, decision recurrences **1, 2, 3**
  (`decision_index` 1/2/3, `maximum_landmarks_per_cell=3`), separation and
  persistence from the frozen `LandmarkContract`
  (`persistence_steps=3`, `minimum_landmark_separation_steps=60` — this is
  the frozen cooldown between recurrences).
- Seeds: **4121–4132** per cell (development-only; already inspected).
  Grouping (frozen): train 4121–4128, one-time held 4129–4132.
- Candidate ranking: frozen `runway` (shortest runway first, tie-break
  vehicle id); candidate count 2 for the new library.
- Treatment: frozen P30 (`activation_speed_ceiling_v1`, `speed_ceiling`
  mode, terminal p30, option steps 20, projected release, hard safety
  projection authoritative, speedMode 31, reference floor 8 m/s).
  Abstain = native IDM; abstain replay = exact control arm.
- Horizon: safety 60 controller steps = 60 s; service horizon 60 steps.
- Reward references: `runs/eval/idm_decentralized_lower_reward_refs_v1.json`
  (SHA-256 `737b9ce4bb1945f7681b807941c86509ae3143128bd0729d2cb2aee5237c5b58`
  — the identical file used by every prior paired artifact in this domain).

## 2. State identity and action library

One library row = one frozen predecision state (seed, cell, recurrence 3-gram,
decision step, identity fingerprints). An option belongs to a row only if its
branch starts from the identical simulator state, uses the identical horizon
and reward references, and reproduces the frozen decision fingerprint.

Action library per row (feasibility-masked): abstain (always), candidate-1
P30 (when an admissible rank-1 candidate exists), candidate-2 P30 (when a
second admissible candidate exists in the same lane). No simultaneous
multi-CAV activation; candidate-2 absence is an infeasible action, not an
alternative state. Recurrences 1/2/3 are **separate states**, not alternative
actions of one state.

Exact abstain-versus-abstain replay identity and exact predecision branch
identity are required before a row is retained.

## 4. Outcomes, deadband and constraints

Per branch: paired 60-second physical effect (equal-weight reference-scaled
reduction of corridor severe-braking count and acceleration energy), dose,
safety/service constraints (complete horizon; at least 16 treatment commands
delivered; no unexpected command; no added collision/teleport; low-TTC
exposure increase ≤ 2 steps; delay-rate increase ≤ 1 s/vehicle; arrival loss
≤ 1; discharge loss ≤ 1; no treatment safety abort when present). Composite
deadband: 0.02 (raised only if replay noise exceeds it). Binary option reward
per the frozen `idm/option_reward.py` contract:
`R(abstain)=0`, `R(activate)=tanh(u)` if all constraints pass, else −2.

## 5. Oracle-headroom definitions (Phase C, frozen)

Baselines: always abstain; always candidate 1; always candidate 2; fixed
5–10% rule (= always candidate 1 in-domain); best fixed recurrence; best
fixed candidate-ranking rule; state-wise retrospective oracle over
abstain/c1/c2; oracle with safety/service constraints enforced; oracle
restricted to actions with adequate dose (≥16 commands).

Hard-report: mean paired reward, physical composite, helpful/harmful/neutral
counts, harmful fraction, coverage, value by penetration/demand/recurrence/
rank, safety/service failures, oracle gain over the best fixed deployable
rule, seeds/cells contributing to the gain.

Oracle headroom passes only if the **constrained oracle** (a) improves mean
policy reward over the best fixed deployable rule by ≥ 0.02; (b) shows
meaningful improvement in ≥ 3 independent development seeds; (c) uses more
than one non-abstain option across the cohort; (d) does not derive the gain
from one outlier; (e) has adequate action and outcome diversity; (f) preserves
the hard safety/service constraints; (g) effects exceed replay noise. If the
constrained oracle cannot materially beat the fixed rule, stop: no RL.

## 6. Observation families (Phase D, frozen)

Tested in increasing complexity, causal predecision penetration-free inputs
only (penetration remains the admission rule outside the actor):

- A. candidate-local snapshot: ego, leader, follower (observable via the
  frozen 134-field local observation), candidate runway, interception time,
  projected P30-versus-native command separation, expected dose;
- B. A plus merge-zone RSU summary (classic RSU observation block: merge
  density/count, speed, variance, ramp state, discharge state, severe/wave
  state);
- C. A/B plus short causal leader/follower history and local speed/wave
  trends (no future frames);
- D. fixed-size V2V neighborhood history (upstream/downstream, masks,
  relative position/speed/accel, identity continuity);
- E. local actor plus centralized training critic (critic-only information
  never enters deployment actions);
- F. causal corridor aggregate ablation — if the actor requires a full-RSU
  corridor summary, the architecture is renamed RSU-assisted decentralized
  actuation.

Model order: rule baseline → ridge/logistic → shallow tree/gradient boosting
(conservative) → small MLP → recurrent only if history shows incremental
value. Grouped splits by seed/scenario; hyperparameters/thresholds from
grouped development predictions only.

Deployable policy authorization (held-development): coverage ≥ 20%; mean
policy reward ≥ +0.01 above the best fixed rule; helpful selections more
frequent than harmful; harmful fraction ≤ 25%; positive in ≥ 2 demands and
both penetration levels (unless a narrower domain is frozen before training);
safety/service preserved; meaningful constrained-oracle recovery; beats
penetration-only, recurrence-only and candidate-ranking baselines. AUROC,
average precision, balanced accuracy, Brier score, calibration = diagnostics
only; AUROC alone authorizes nothing.

## 7. Reward audit and training gates (Phases E–G, frozen)

Reward audit (only if D passes): exact abstain-replay zero, branch-order and
worker-count invariance, effect reproduction (≤1e-12), sign agreement,
substantial-effect ordering, finite bounds, safety/service override, no
seed/future leakage, focused tests + full `python -m pytest -q` green.

Training (only if E passes): one-step paired contextual-bandit first
(sequential semi-Markov only if justified by evidence); shared policy across
candidate decisions; no ordinary variable-lifetime per-step MAPPO. Gates:
wrapper determinism smoke → 2,000-sample learning smoke → 10,000-sample value
test (held reward ≥ +0.01 over best fixed rule, oracle recovery, helpful >
harmful, harmful ≤ 25%, adequate coverage, positive across the frozen domain,
stability across ≥ 2 initializations when runtime permits) → dev campaign
only after all pass; resumable checkpoints under `runs/rllib/`; checkpoint
selection on development data only; simple trained models retained if they
beat PPO.

## 8. Prohibited leakage and claims

Forbidden inputs: seed, future frames, realized dose, outcome/reward, release
reason, postdecision safety/service values, branch identifiers. Prohibited:
postdecision information; discarding harmful/failed cases; prospective seeds
(4107–4132 stay development-only); paper-scale data; wall predictor training;
ordinary per-step MAPPO; claiming success from training return alone;
claiming that these results generalize before prospective acceptance.
