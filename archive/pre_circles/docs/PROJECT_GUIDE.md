# Traffic Shepherd RL — Project Guide

Full reference for every file in the build and every command to run it.

---

## 1. Project overview

**Traffic Shepherd RL** trains and evaluates mixed-autonomy highway merge
controllers using SUMO (simulation) + TraCI (Python interface) + Ray RLlib
(reinforcement learning). Three learned baselines are compared against
rule-based and no-op controllers:

| Baseline | Actions | Reward | Critic |
|----------|---------|--------|--------|
| **Selfish** | Continuous acceleration (`[-3, +3]` m/s²) | Personal (speed + comfort + safety) | Local PPO/IPPO |
| **Flat-MARL** | Continuous acceleration (`[-3, +3]` m/s²) | Shepherd (human-centric, shared with Shepherd) | MAPPO centralized |
| **Shepherd** | 5 semantic modes (non-intervention, gap, stabilize, conservative, release) | Shepherd (human-centric) | MAPPO centralized |

All three use RLlib's PPO optimization objective and a shared CAV policy. The
baseline distinction is the critic information:

- **Selfish:** independent PPO/IPPO. Its actor and value critic each receive
  only the current CAV's local 128-dim encoding.
- **Flat-MARL and Shepherd:** MAPPO. Their actors receive only local
  observations, while their centralized critics pool all active CAV embeddings
  per component: ego via masked mean, neighbors via trust-weighted sum, and
  zone via masked mean.

Selfish and Flat-MARL are **continuous longitudinal-acceleration**
controllers. Their policies output one real-valued acceleration in
`[-3, +3] m/s²`; Shepherd instead selects one of five semantic control modes.

The sibling SUMO network lives at `../highway_merge_shepherd`. Its demand is
**controlled flow, not randomTrips**: `osm.demand.{light,medium,dense}.rou.xml`
declare two explicit flows (mainline + on-ramp) over a 900 s departure window —
light 1400/600, medium 2600/600, dense 2900/600 veh/h — generated by
`tools/build_demand.py`. Driver heterogeneity comes from the route file's
embedded `vTypeDistribution` (10% aggressive / 70% normal / 20% cautious), so
pure-SUMO baselines and TraCI-controlled runs share the exact same driver
mixture. See `../highway_merge_shepherd/density_presets.txt` for the tier
table, measured All-HDV metrics, and the legacy randomTrips notes.

## 2. Algorithm and action-space definitions

### Selfish: local PPO/IPPO with continuous acceleration

Selfish uses RLlib PPO with a parameter-shared policy across CAV agents. This
is commonly called **IPPO** in a multi-agent environment because each CAV's
actor and critic use only that agent's local observation; no CAV-peer
observation is packed for the critic.

The action space is `Box(low=-3.0, high=+3.0, shape=(1,))`. The PPO policy's
Gaussian action distribution outputs one real-valued longitudinal acceleration
in m/s², clipped to this range before execution.

At every 1 s environment step, the selected acceleration is translated to:

```text
v_next = clip(v_current + acceleration * dt, 0, max_speed)
```

and sent to SUMO with `traci.vehicle.setSpeed`. Therefore, Selfish outputs
only a **continuous longitudinal acceleration command**. It has no semantic
Shepherd modes and no centralized critic.

### Flat-MARL: MAPPO with continuous acceleration

Flat-MARL uses the exact same continuous `Box([-3, +3])` acceleration action and physical
translation as Selfish. Its difference is not the actuator: it uses the
human-centric Shepherd reward and a MAPPO centralized critic. The critic sees
all active CAV local observations, but the actor still outputs only one
continuous acceleration for its own CAV.

For the Shepherd reward's intervention-cost term only, Flat-MARL maps the
near-zero acceleration to `mode=0` and every nonzero acceleration to `mode=1`. This
synthetic mapping does **not** change how its vehicle is controlled.

### Shepherd: MAPPO with semantic discrete modes

Shepherd uses `Discrete(5)`: its action indices select the semantic
control laws `non_intervention`, `gap_creation`, `flow_stabilization`,
`conservative_following`, and `release`. `ShepherdActionEngine`
(in `env/actions.py`) translates those modes into temporary headway and speed
interventions.

### Critic comparison

| Baseline | Actor observation | Critic observation | Physical policy output |
|---|---|---|---|
| Selfish | Local | Local | Continuous acceleration |
| Flat-MARL | Local | All active CAVs, component-pooled | Continuous acceleration |
| Shepherd | Local | All active CAVs, component-pooled | Shepherd-mode index |

## 4. File-by-file reference

### Root scripts and modules

| File | What it does |
|------|-------------|
| `train.py` | Main training entry point. Builds local PPO/IPPO for Selfish and MAPPO for Flat-MARL / Shepherd, runs the training loop, and saves checkpoints + metrics. |
| `train_all.py` | Runs the selected baselines sequentially via subprocess calls to `train.py`. Configurable with `--baselines`, `--total-timesteps`, `--logdir-root`, `--resume`. |
| `evaluate_policy.py` | Evaluates a single policy (learned or baseline) on one density/penetration. Produces travel-time + TTC metrics. Writes tripinfo + FCD for offline analysis. |
| `evaluate_sumo_baseline.py` | Pure SUMO evaluation with no learned policy (all-HDV baseline). Runs SUMO directly, produces tripinfo + FCD, prints travel-time + TTC. |
| `models.py` | `FeatureEncoder` — shared encoder for all baselines: ego(4)→32, neighbors(20×5)→DeepSets (one shared Linear(4→32)+ReLU per neighbor from rel_dist/rel_speed/rel_lane/turn_signal, trust as pooling weight only)→trust-weighted mean→32, zone(7)→64, concatenated to 128; `forward_components()` returns the parts separately for the critic. `SelfishPPOModel` — local PPO/IPPO model (Selfish). `MAPPOModel` — MAPPO model (Flat-MARL / Shepherd): local actor + per-component pooled centralized critic. |
| `evaluation.py` | `run_sumo_evaluation()` — SUMO subprocess producing tripinfo + FCD. `evaluate_travel_time()` — parses tripinfo XML → mean/P90 travel time (all / mainline / ramp). `evaluate_ttc()` — parses FCD XML → TTC violation count below 1.5 s. |

### `config/`

| File | What it does |
|------|-------------|
| `constants.py` | Single source of truth for `MODE_NAMES` (5 Shepherd modes), `RL_SPEED_MODE` (7 — regard safe speed + max accel/decel, so SUMO clamps RL `setSpeed()` to the safe car-following speed), continuous acceleration bounds (`-3` to `+3` m/s²), SUMO edge IDs (`MAINLINE_EDGE`, `RAMP_EDGE`), and reward term names. |
| `defaults.py` | `DEFAULT_CONFIG` dict with all tunable parameters: `observation_radius=200`, `neighbor_radius=200`, reward weights, flow-stab knobs, mode comfort bounds (`mode_max_decel`/`mode_max_accel`/`mode_deadband`), trust lambda, HDV proportions, `max_cavs_critic=64`, etc. `merge_config()` merges user overrides with defaults. |

### `env/`

| File | What it does |
|------|-------------|
| `core.py` | `TrafficShepherdMultiAgentEnv` — the Gymnasium multi-agent env. Manages SUMO lifecycle, CAV selection, observations, actions, rewards. Accepts optional `reward_fn=` and `action_engine=` constructor hooks so custom rewards / actuators can be swapped in without editing the file. Returns local observations for Selfish and packed peer observations for MAPPO. |
| `rllib_wrapper.py` | `TrafficShepherdRLlibEnv` — wraps the Gym env as a Ray `MultiAgentEnv`. Maps SUMO vehicle IDs to stable RLlib agent IDs (unique on re-entry after done). Handles terminal transitions correctly. |
| `rewards.py` | **All reward math.** `compute_shepherd_reward` — `R = w_e·R_eff + w_s·R_safe + w_t·R_stab + w_f·R_fair + w_c·C_ctrl`, with each term a small named helper. `compute_selfish_reward` — personal speed + comfort + safety. `JerkTracker` (da/dt) and `TimeLossTracker` (per-step getTimeLoss rate) provide state for stability / fairness. |
| `actions.py` | **All action execution.** `ShepherdActionEngine` — 5-mode execution: `flow_stabilization` uses ahead-only 150-200 m band + EMA + rate-limited braking; `gap_creation` / `release` / `conservative_following` rate-limit toward per-mode `speed_factors` targets with comfort bounds (`mode_max_decel` / `mode_max_accel` = 1.0 m/s², `mode_deadband`); the selected mode persists until the policy picks another — no auto-fade, no coordination downgrade. `apply_continuous_acceleration()` — continuous acceleration via `setSpeed` + `speedMode=6` (Selfish / Flat-MARL). |
| `features.py` | `collect_neighbors()` — up to `max_neighbors` nearest vehicles with distance / speed / lane / signal features. `TrustTracker` — EMA trust (Trust-MARL style; CAV-to-CAV prior 0.8). `build_zone_features()` — pre-merge / merge / ramp stats. `time_to_merge()` — normalized time for ego to reach the merge junction. `ObservationAssembler` — packs ego(4) + zone(7) + count(1) + neighbors(20×5) into a fixed vector. |
| `vehicles.py` | `CAVSelector` — seeded, reproducible selection of which vehicles are CAVs based on penetration rate. `HDVTypeAssigner` — assigns aggressive / normal / cautious driver types to HDVs at departure, with seeded proportions. |
| `mappo.py` | `pack_mappo_observation()` — packs local obs + peer obs + trust weights for the CTDE critic. `unpack_mappo_observation()` reverses it. `acceleration_to_shepherd_mode()` maps near-zero/nonzero continuous acceleration only for Flat-MARL's reward control-cost term. |
| `traci_query.py` | Consolidated TraCI readers: `leader_ttc()`, `vehicles_within_radius()`, `ahead_lane_speeds()` (150-200 m band), `percentile()`, `percentile_or_zero()`. Used by rewards, actions, and evaluation. |
| `sumo_utils.py` | `start_sumo()` / `close_sumo()` — manages TraCI connections with free-port selection. Vehicle ID queries. |

### `policies/`

| File | What it does |
|------|-------------|
| `__init__.py` | `Policy` and `DirectControlPolicy` abstract interfaces, plus re-exports of every concrete policy. |
| `baselines.py` | `NoOpPolicy` (always mode 0), `RandomPolicy` (random mode), `ConstantSpeedPolicy` (non_intervention, mode 0 — equivalent to no_op under shepherd mode), `RuleBasedMergePolicy` (kinematic yield to merge intent). |
| `rllib_policy.py` | `RLlibPolicy` — loads an RLlib checkpoint and runs inference. Detects the environment action space and returns a scalar acceleration for continuous policies or a mode index for Shepherd. |
| `traci_control.py` | TraCI helpers for rule-based policies: kinematic safe speed, merge detection, adjacent-lane queries. |

### `tools/`

| File | What it does |
|------|-------------|
| `batch_eval.py` | Full evaluation grid: baselines × densities × penetrations. Saves per-run JSON + rolling `summary_all.json`. Parameterized with `--baselines`, `--densities`, `--penetrations`. |
| `print_summary.py` | Prints `summary_all.json` as a compact table. Accepts optional path argument. |
| `build_baseline_pdf.py` | Generates `docs/reports/baseline_report.pdf` — a ReportLab PDF write-up of baselines, modes, reward math, and end-to-end flow. |

## 5. Customizing the reward or the action execution

The two experiment surfaces live in single files with documented headers:

- **Reward** — edit `env/rewards.py`. Each Shepherd term is a small named
  function (`_efficiency`, `_safety`, `_stability`, `_fairness`,
  `_control_cost`) combined in `compute_shepherd_reward`. Weights come from
  `reward_weights` in `config/defaults.py` and can be overridden per run via
  `env_config`.
- **Discrete-action execution** — edit `env/actions.py`. Each Shepherd mode
  is executed by `ShepherdActionEngine` (`_flow_stabilization` for mode 2,
  `_gentle_mode` for the other non-zero modes), with the mode-to-physics
  mapping described in the module docstring.

For experiments that should not touch the defaults, both are injectable:

```python
from env.core import TrafficShepherdMultiAgentEnv


def my_reward(env, action_dict, obs):
    return {agent_id: 0.0 for agent_id in action_dict}


env = TrafficShepherdMultiAgentEnv(env_config, reward_fn=my_reward)
# or: TrafficShepherdMultiAgentEnv(env_config, action_engine=MyEngine(...))
```

`reward_fn(env, action_dict, obs)` must return `{agent_id: float}`.
`action_engine` must provide `apply_all(action_dict, cav_ids=...)` and
`reset()`.

## 7. Training commands

### Single baseline

```powershell
cd D:\research\traffic_shepherd_rl

# Train Selfish (100k steps, medium density, 10% CAV)
python train.py --baseline selfish --total-timesteps 100000 --logdir runs/rllib/selfish

# Train Flat-MARL
python train.py --baseline flat_marl --total-timesteps 100000 --logdir runs/rllib/flat_marl

# Train Shepherd
python train.py --baseline shepherd --total-timesteps 100000 --logdir runs/rllib/shepherd
```

### Resume training to a larger budget

```powershell
# Resume the same run to 1M steps
python train.py --baseline selfish --total-timesteps 1000000 --resume --logdir runs/rllib/selfish

# Resume from a specific checkpoint
python train.py --baseline shepherd --total-timesteps 1000000 `
  --from-checkpoint runs/rllib/shepherd/checkpoints/iter_50 --logdir runs/rllib/shepherd
```

### Train all three sequentially

```powershell
python train_all.py --total-timesteps 100000
# subset / resume:
python train_all.py --baselines flat_marl shepherd --resume
```

### Training outputs

Each run writes to `{logdir}/`:
- `metrics.csv` / `metrics.jsonl` — per-iteration metrics
- `tb/` — TensorBoard event files (scalars under `train/*`, x-axis = env timesteps)
- `progress.txt` — live progress (steps done / target / ETA)
- `train_state.json` — iteration, timesteps, best reward (for clean resumes)
- `checkpoints/best/` — best checkpoint by `policy_reward_mean`
- `checkpoints/final/` — final checkpoint
- `checkpoints/iter_N/` — periodic checkpoints (every `--save-every` iterations)

| Parameter | Default | Description |
|-----------|---------|-------------|

| `neighbor_radius` | 200.0 | Meters for neighbor feature collection |
| `max_neighbors` | 20 | Max neighbors in observation |
| `max_cavs_critic` | 64 | Max peer CAVs packed for MAPPO critic (≥ max concurrent active CAVs; measured 26 at p20 dense via `tools/measure_max_active_cavs.py`) |
| `base_tau` | 1.0 | SUMO desired time headway (s) |
| `trust_lambda` | 0.2 | EMA rate for trust updates |

### Flow stabilization (Shepherd mode 2)

| Parameter | Default | Description |
|-----------|---------|-------------|
| `flow_stab_near` | 150.0 | Near edge of ahead band (m) |
| `flow_stab_far` | 200.0 | Far edge of ahead band (m) |
| `flow_stab_ema_alpha` | 0.3 | EMA smoothing for downstream speed |
| `flow_stab_deadband` | 0.5 | m/s deadband to avoid chatter |
| `flow_stab_a_max_dec` | 1.0 | Max deceleration rate (m/s²) |
| `flow_stab_a_max_acc` | 1.0 | Max acceleration rate (m/s²) |
| `flow_stab_preview_gain` | 0.5 | m/s below v_down for anticipation |

### Mode targets and comfort bounds

Each non-zero mode (except `flow_stabilization`) rate-limits the CAV toward
`speed_factors[mode] × v_ego` while adjusting headway by `tau_deltas[mode]`
(gap_creation 0.90 / +0.6 s, conservative_following 0.95 / +0.4 s, release
1.05 / −0.3 s). The selected mode persists until the policy picks another —
no auto-fade, no coordination downgrade. Per-step speed change is capped by
the comfort bounds below, so any share of CAVs may act simultaneously without
creating stop-and-go waves.

| Parameter | Default | Description |
|-----------|---------|-------------|
| `mode_max_decel` | 1.0 | Max braking rate for mode changes (m/s²) |
| `mode_max_accel` | 1.0 | Max acceleration rate for mode changes (m/s²) |
| `mode_deadband` | 0.5 | m/s deadband to avoid chatter |

### Reward weights

| Parameter | Default | Description |
|-----------|---------|-------------|
| `reward_weights.efficiency` | 1.0 | Ego speed / max speed |
| `reward_weights.safety` | 1.0 | Ego hard brake/TTC/collision − 2 × violating-neighbor share (bounded [−9, 0], density-independent) |
| `reward_weights.stability` | 0.5 | Accel + jerk + local jerk |
| `reward_weights.fairness` | 0.5 | Signed HDV-delay improvement vs All-HDV baseline rate `fairness_r_ref` (bounded [−1, +0.5]) |
| `reward_weights.control_cost` | 0.1 | -1 if mode ≠ 0, else 0 |
| `fairness_r_ref` | per density | All-HDV mean per-step getTimeLoss rate — light 0.074 / medium 0.22 / dense 0.38 (`FAIRNESS_R_REF_BY_DENSITY`, from `runs/task5_acceptance/baseline_*.json`); injected by train.py / evaluate_policy.py, fallback 0.5 |
