# PACKV3_FIX — pack_v3 contributes training windows (owner-approved fix #1)

CPU-only, metadata/mmap; no training, GPU, SUMO, or wall. Branch `wms/packv3fix`.
Evidence generated by `_out/packv3fix_tools/{build_packv3fix,verify_packv3fix,diag_packv3}.py`.

## 1. Diagnosis — why pack_v3 yielded 0 windows

**Root cause: a silent pack-name/basename mismatch in the window-list filter.**

`wms/train.py::_select_lpo_positions` called
`wms/lpo.py::window_keys(window_list, packs=names)` where `names =
lpo.pack_names(paths)` are the pack **directory basenames**. `window_keys`
keeps only list entries whose `pack` field is in `names`. The LPWO v2 lists name
the packs canonically (`pack_v3`, `pack_dspeed`, `pack_damping`), but on the
boxes the base pack was staged under a different basename:

| run | base pack path (box) | basename |
|---|---|---|
| C1FAST `full_struct` / MAIN2 gpuA | `/root/autodl-tmp/wmn1_m1_45c9032_20261003_A1/work/pack` | `pack` |
| MAIN2 gpuB no-brake | `/root/autodl-tmp/pack_v3_sparse` | `pack_v3_sparse` |

So the base pack's name never matched `pack_v3`, and every `pack_v3` entry was
removed from the keep set **before** matching. Because `want` filtered them out,
they were never reported as "missing" either (no fail-closed), so they simply
contributed zero windows.

Reproduction (real local data, `D:/rd-staging/wmn1_feat/pack_v3` + a
`pack_name_list` override, `_out/lpwo_v2` lists):

| scenario | `window_filter` | `kept_by_pack` |
|---|---|---|
| canonical basename `pack_v3` | requested 1172 / matched 1172 | `pack_v3 381, pack_dspeed 560, pack_damping 231` |
| box basename `pack` (pre-fix) | requested 791 / matched 791 | `pack_dspeed 560, pack_damping 231` |
| box basename `pack` (post-fix) | requested 1172 / matched 1172 | `pack_v3 381, pack_dspeed 560, pack_damping 231` |

The middle row reproduces the box receipt exactly (`kept_by_pack = {pack_damping:
231, pack_dspeed: 560}`, `window_filter requested=791 matched=791`, and
`identity_rows: 3`).

**Ruled out:**

* **Identity sidecar rows missing — no.** The verified local sidecar
  `E:/rd-wt/ws-p2/_ext/identities` is `2153 x 192` `int64` and covers **exactly**
  the 2153 TRAIN manifest positions of `pack_v3` (0 missing, 0 non-TRAIN). The
  `identity_rows: 3` field in every receipt is the **number of identity sidecar
  directories** (`len(identity_rows)` in `from_real_packs`), not a row count; the
  earlier "3 rows" reading is a misreading of that field.
* **Key mismatch between window ids and sidecar keys — no.** The LPWO v2 lists
  carry 381 train + 53 val `pack_v3` windows; all 381 train keys match the pack_v3
  manifest items exactly under the loader's own key `(batch, world, arm,
  round(t0_s,3))`.
* **Outcomes labels missing — no.** The mixed-split base pack requires the
  TRAIN-only outcome sidecar (`labels_cov_20261004T072826Z`, bound to the
  pack_v3 manifest); it exists and is staged into the fix bundle. The box never
  reached a pack_v3 decode, so this was never the visible failure.
* **LPWO v2 lists lacking pack_v3 entries — no.** They contain them.

## 2. Fix

1. **Loader (`output/wd01/wm_n1/wms/train.py`)** — new
   `_resolve_window_pack_names`: when a window-list `pack` name does not match a
   pack-directory basename, resolve it to the unique corpus pack whose TRAIN item
   keys cover its windows (metadata only). If a name is absent or ambiguous it
   **refuses** instead of silently contributing zero. `_select_lpo_positions` uses
   it and records the applied mapping in the receipt as `pack_name_resolution`.
   This makes pack_v3 contribute regardless of the staged basename (`pack`,
   `pack_v3_sparse`, `pack_v3`).
2. **New sidecar bundle `_out/sidecars_packv3_v2/`** with `BUILD_RECEIPT.json`:
   * `identities/` — the verified `2153 x 192` sidecar (byte copy; sha256 recorded;
     coverage == the 2153 TRAIN manifest positions).
   * `outcomes/` — the TRAIN-only outcomes sidecar (`wm_n1_train_outcomes_sidecar/3`,
     71 622 rows, bound to the same pack manifest) so the mixed pack's other-split
     labels are never opened.
3. **New window lists `_out/lpwo_v3/`** with `BUILD_RECEIPT.json`, derived from
   `E:/rd-wt/ws-wallc1/_out/lpwo_v2` (rule (a) preserved exactly: no PI arm, no PI
   event, no wall-family arm, no wall ownership, no LPWO-excluded key) after:
   * rule (b): holdout guard `tools/holdout_guard.py` +
     `protocols/holdout_exclusions.json` (13 excluded worlds; matched by world id
     only) and sealed tokens CAL/HOLDOUT/chunk-5/J4B/INC1 — never opened;
   * rule (c): disjoint from the wallc1 eval sets
     `_out/wallc1_states_v2/{wall_same,wall_pilot,seen_controls}`.

## 5. How a future training run passes the new paths

The chain only needs the ~21 MB sidecar bundle and the small v3 lists; the
50 GB pack is **not** re-copied and may keep any basename:

```bash
PACK_V3=<staged base pack>                 # basename may be pack / pack_v3_sparse / pack_v3
PACK_DSPEED=.../pack_dspeed ; PACK_DAMPING=.../pack_damping
IDENTITIES_V3=<this worktree>/_out/sidecars_packv3_v2/identities
IDENTITIES_DSPEED=... ; IDENTITIES_DAMPING=...
TRAIN_OUTCOMES=<this worktree>/_out/sidecars_packv3_v2/outcomes
OVERLAY_DSPEED=... ; OVERLAY_DAMPING=...
WINDOWS_TRAIN=<this worktree>/_out/lpwo_v3/windows_train_noPI_noWall.json
WINDOWS_VAL=<this worktree>/_out/lpwo_v3/windows_val_noPI_noWall.json
EXCLUDE=<this worktree>/_out/lpwo_v3/excluded_runs_PI_wall_v3.json
# also export WM_N1_TRAIN_IDENTITIES=$IDENTITIES_V3 WM_N1_TRAIN_OUTCOMES=$TRAIN_OUTCOMES
```

The list `pack` field stays canonical (`pack_v3`); the loader resolves it to the
staged basename and records `pack_name_resolution` in the receipt.
