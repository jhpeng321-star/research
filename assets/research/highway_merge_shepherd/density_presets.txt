Traffic density presets — controlled mainline + ramp flows (900 s demand window)
=================================================================================

Demand is NO LONGER randomTrips. Each tier is generated by
tools/build_demand.py (in the sibling traffic_shepherd_rl repo) as two explicit
SUMO flows — mainline and on-ramp — over a fixed 900 s departure window, so
bottleneck inflow is directly controllable in veh/h. Driver heterogeneity is
declared inline in the route file as a vTypeDistribution (mixture "standard":
10% aggressive / 70% normal / 20% cautious), so pure-SUMO baselines and
TraCI-controlled runs share the exact same driver mixture.

Tier    Mainline (veh/h)   Ramp (veh/h)   Window   Mixture    Route file                     Config
-----   ----------------   ------------   ------   --------   ----------------------------   ------------------
light   1400               600            900 s    standard   osm.demand.light.rou.xml       osm.light.sumocfg
medium  2600               600            900 s    standard   osm.demand.medium.rou.xml      osm.medium.sumocfg
dense   2900               600            900 s    standard   osm.demand.dense.rou.xml       osm.dense.sumocfg

Measured All-HDV baseline (no RL), 3 seeds 42/43/44, mean ± std
(via: python evaluate_sumo_baseline.py <tier> --seeds 42,43,44 --re-run):

Tier    Travel time (s)   timeLoss (s)    Collisions    Teleports   Arrived   Throughput (veh/h)
-----   ---------------   -------------   -----------   ---------   -------   ------------------
light   53.77 ± 0.15      3.97 ± 0.17     0.00 ± 0.00   0           501       1880 ± 6
medium  67.23 ± 1.87      15.10 ± 1.83    1.33 ± 0.58   0           800       2973 ± 5
dense   84.68 ± 6.05      32.28 ± 6.23    2.00 ± 2.65   0           876       3171 ± 29

Acceptance bands (all three tiers pass): light timeLoss <= 5 s and 0 collisions;
medium timeLoss 10-30 s; dense timeLoss 30-60 s, 0 teleports, collisions <= 2.
Note: dense sits at the lower edge of its band and exactly at the collision cap —
seed-to-seed variance is high there (timeLoss 27.4-39.3 s, collisions 0-5/seed).

Regenerate demand:
    cd ../traffic_shepherd_rl
    python tools/build_demand.py --level light  --mainline-vph 1400 --ramp-vph 600 --duration 900 --out-dir ../highway_merge_shepherd
    python tools/build_demand.py --level medium --mainline-vph 2600 --ramp-vph 600 --duration 900 --out-dir ../highway_merge_shepherd
    python tools/build_demand.py --level dense  --mainline-vph 2900 --ramp-vph 600 --duration 900 --out-dir ../highway_merge_shepherd

Run simulation:  run.bat light|medium|dense   or   sumo -c osm.<tier>.sumocfg
Outputs are written per level (e.g. stats.light.xml, tripinfos.dense.xml,
edgeData.medium.xml; seeded eval runs use stats.<tier>.seed<N>.xml etc.).

Legacy (kept for reference only, NOT used to build the tiers):
build_all.bat / build_light.bat / build_medium.bat / build_dense.bat /
build_trips.bat drive the old randomTrips pipeline
(osm.passenger.*.trips.xml -> duarouter). The old fixed-count tiers
(light 58 / medium 220 / dense 300 vehicles) are superseded by the
controlled-flow tiers above.
