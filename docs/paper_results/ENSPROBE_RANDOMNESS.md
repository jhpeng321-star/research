## Active world-generation randomness, fixed once a world is generated
- **Departures:** `traffic_shepherd/scenarios.py::request_schedule`: independent Python `random.Random("damping_requests_v1:{seed}:{stream}")` for mainline/ramp, exponential interarrival times, explicit departure timestamps rounded6decimals. Mainline constant demand through1200s, then ramps down; ramp400vph. Not a SUMO probabilistic flow. Changing only SUMO `--seed` does not redraw these arrivals.
- **CAV assignment:** independent identity-keyed `damping_cav_v1:{seed}:{identity}` uniform draw compared to penetration. Penetration is nested and leaves requests/HDV draw stream unchanged. Frozen CAV identities, no runtime reassignment.
- **Driver heterogeneity:** textbook HDVs use `textbook_driver_v1:{seed}:{identity}` Python stream: truncated Gaussian speedFactor/minGap; jointly truncated lognormal accel/tau (corr(ln a,ln1/tau)=.4); truncated lognormal decel; uniform lcCooperative/lcAssertive/lcSpeedGain/impatience; values rounded4decimals. CAVs use one fixed median type. This is parameter uncertainty across worlds, not per-tick noise. Legacy generator's separate `damping_type_v1`10/70/20 draw is calculated but overwritten by textbook selection; inactive as a behavioral source here.

## SUMO runtime sources and switches
- **Global seeds:** `traffic_shepherd/simulation.py::start_sumo` explicitly passes `--seed world_seed`, no `--random`;0.5s physics,1s control. SUMO has separate loading/flow/driving/device RNG instances initialized from this seed. RNG existence alone does not make a configured model stochastic.
- **Car following:** generator `population.vtype_attrs` selects IDM and writes `sigma=0`; IDM does not implement Krauss-style dawdling even if nonzero sigma were written. No EIDM/Krauss, driver-state device, action noise or process-noise term is enabled by this generator. Braking/emergencyDecel and collision avoidance are deterministic rules.
- **Desired speed:** textbook `speedFactor` varies between HDVs via the Python world stream; CAV speedFactor1. SUMO `speedDev=0` explicitly removes SUMO's default10% per-vehicle speed-factor draw. Existing and future vehicles retain their generated factors when only SUMO seed changes.
- **Insertion:** explicit vehicle requests; `departLane="best"`, `departSpeed="max"`, default base position; no random-depart-offset or random position/speed/lane. SUMO's `MSEdge::getDepartLane(BEST_FREE)` selects best continuation then deterministic largest-gap/occupancy lane; safety can delay insertion, coupling source queues to traffic without an additional Poisson draw. No forced/random-free insertion enabled.
- **LC2013:** default nonsublane model; heterogeneous strategic/cooperative/speed-gain/assertiveness/impatience parameters influence deterministic decisions. No `lcSigma` written, default0; no lateral drift. No `lcOvertakeRight` written, default0, so probabilistic right-overtake branch short-circuits. Variables named `mySpeedGainProbability*`/`myKeepRightProbability` are accumulating deterministic decision propensities, not evidence of RNG sampling.
- **Junction/merge:** audited network has priority and dead-end junctions, not random right-before-left/all-way-stop arbitration. No generated jmSigma or stochastic junction overrides; IDM/LC gap acceptance, impatience and right-of-way produce state-dependent merges, not configured random coin flips. No randomized signal program or junction device.
- **Rerouting/routes/devices:** generator copies fixed named mainline/ramp routes, emits explicit vehicles; no routeDistribution, rerouting device/probability/threads, randomized weights, randomTrips or OD randomization launched. Network/config contain no behavioral param overrides. Original route-edge strings and realized assignments are not inspected; assignment-dependent claims remain undetermined.
- **Controller/sensing:** native uses no policy sampling. Speed-only MAPPO uses the frozen iter169 export (`d9042cc5…`), deterministic deploy path; WMDATA sets `C4_POLICY_STOCHASTIC=0`, `C4_POLICY_ACCEL_NOISE=0`. Native SUMO lanes remain active. No observation dropout/noise is added in the probe.

## Interpretation and versioned references
This setup has substantial **world-generation** randomness but no identified active **continuation process noise** once requests, drivers and the physical state are fixed. The ensemble measures any residual SUMO seed sensitivity; a narrow/degenerate ensemble cannot establish that real merging traffic is deterministic. Re-generating requests with a new world seed would change more than the continuation RNG and answers a different question.
SUMO1.27.1 documentation: [Randomness](https://github.com/eclipse-sumo/sumo/blob/v1_27_1/docs/web/docs/Simulation/Randomness.md), [SaveAndLoad](https://github.com/eclipse-sumo/sumo/blob/v1_27_1/docs/web/docs/Simulation/SaveAndLoad.md). Version-pinned implementation checks: `src/microsim/lcmodels/{MSAbstractLaneChangeModel,MSLCM_LC2013}.cpp` (lcSigma/lcOvertakeRight defaults and drift guards), `src/microsim/MSEdge.cpp` (best-lane insertion). Save/load documentation warns CF/LC internal state is not fully preserved; the requested physical equality gate is deliberately weaker.
